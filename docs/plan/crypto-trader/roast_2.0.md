### STAGE 2: THE EV SCORER — "Built, Instantiated, Never Used for Decisions"

> [!CAUTION]
> **The fatal flaw:** The EV scorer runs in a **"parallel path"** — it computes scores alongside the old system but **doesn't drive any decisions.**

Look at `decision_engine.py:424-442`:
```python
# ─── PHASE 1: EV COMPOSITE SCORING (parallel path) ─────────────
# Compute EV score for both directions to track rejected signals
ev_scores: dict[str, tuple[float, float]] = {}  # direction -> (ev_score, threshold)
for dir_name in ["LONG", "SHORT"]:
    try:
        ev_score, ev_threshold = await self._compute_ev_score(...)
        ev_scores[dir_name] = (ev_score, ev_threshold)

        logger.debug("EV scoring failed for %s %s: %s", symbol, dir_name, e)
```

After computing the EV score... **it goes into a dictionary that is never read again.** The actual decision is still made by the old `score >= effective_gate` comparison at line 852. The EV score is computed, logged, and forgotten.

You built a thermometer, screwed it into the dashboard, and then kept guessing the temperature by sticking your hand out the window.

**Same story with `RejectedSignalTracker`**: it's tracking rejected signals (great!), but since the EVScorer isn't deciding anything, what it's tracking is "signals rejected by the old system that the new system also observed." That's a tautology, not alpha research.

### STAGE 7: THE CONSECUTIVE LOSS BLOCK — "Checked Twice, Remembered Forever"

This is a small detail, but it captures the systemic problem:

```python
# decision_engine.py:894
if await self.check_consecutive_losses(symbol, regime):
    return None

# live_loop.py:286
if engine and await engine.check_consecutive_losses(symbol, signal.regime):
    return
```

**The same consecutive loss check runs twice** for every signal. Once in DecisionEngine and once in live_loop. Same function, same data, same result. The second call is redundant but adds latency.

More importantly: `check_consecutive_losses` blocks a symbol after 3 losses regardless of market conditions. If SOL/USDT has 3 losses in CHOP and then enters a TREND_BULL breakout, it's still blocked. The loss streak might have been entirely regime-dependent, but the block is regime-agnostic.

## ABOUT THE "HYBRID INTELLIGENCE" — LET'S BE HONEST

The Hybrid Decision Engine IS intelligent. The statistical features it computes (beta, correlation, ATR percentile, EMA overextension, volume spikes) are **exactly the right features**. The AI integration through NineRouterService is clean. The fallback path (stat-only when AI times out) is correctly designed.

But intelligence without agency is just analysis paralysis. Your hybrid system is doing what a nervous analyst does: computing 50 metrics, building a perfect picture of the market, and then deciding... "it's too risky." Every time. In every regime. For every symbol.

A profitable hybrid system would:
1. Use the statistical engine to **score opportunities** (not block them)
2. Use the AI to **rank and size** (not veto)
3. Use the APM to **manage risk** post-entry (which it already does beautifully)
4. Use the rejected signal tracker to **learn what it's missing** (which it's collecting but nobody's reviewing)

You have all four components built. You just haven't connected them in the right order. The wires are there. The circuit board is there. You just need to solder them together and stop treating "AI says no" as gospel.
